The Thinking · Why These Systems
Question 01
Why build an annotator before building any model?
Because bad ground truth produces bad models regardless of architecture. Most CV engineers start with a pre-trained model and discover data quality problems later. I started with the data problem — built the annotation tool first, established ground truth standards for each object type, then trained models against verified data. The annotator also supports predicted overlay: you load model predictions alongside manual labels and immediately see where the model diverges. That's how you build a retraining loop that targets real failures, not synthetic edge cases.
Question 02
Why TrackNet for ball tracking instead of a detection model?
Standard object detectors fail on small, fast-moving objects — a cricket ball at 140 km/h occupies ~3–5 pixels per frame and spends several frames as a blur rather than a distinct object. TrackNet was designed specifically for this problem: it takes a sequence of frames as input and predicts the heatmap of where the ball is, using temporal context to infer position through frames where the ball is invisible. Fine-tuning on sport-specific footage — with annotated occlusion, release, and landing events — makes it meaningfully more accurate than using generic weights.
Question 03
Why audio-first for bat-ball contact detection?
Visual-only event detection breaks down at precisely the moments that matter most — when the bat meets the ball, the camera is often mid-pan, the ball is occluded by the bat, or the frame rate is too low to capture the exact moment. Audio doesn't have this problem: bat-ball contact produces a distinct acoustic signature that exists even in noisy nets sessions. The audio signal is the most reliable event anchor available, so the system uses it as the primary detection method and uses visual frames only for downstream context, not for detection itself.
Question 04
Why video-only biomechanics instead of wearables?
Wearables require athletes to change their equipment and routine, introduce calibration overhead, and are impractical for retrospective analysis of existing footage. A video-only pipeline works on any footage that already exists — archived training sessions, match recordings, academy clips — without instrumenting the athlete. Mediapipe gives reliable joint keypoints at 30fps on standard hardware. Combined with shuttle trajectory from the tracking system, you can derive smash speed and kinematic consistency metrics without any hardware dependency.

Foundation Layer · Built First
Internal Infrastructure · Google Cloud Run · Production
Sports Annotation &
Ground Truth Engine
A production-grade internal labelling tool built from scratch to handle multi-sport, multi-object annotation with keyboard-driven workflows. Supports both manual annotation and predicted data overlay in the same interface — so you can benchmark model outputs against ground truth directly, without switching tools.

Built before any model was trained. The decision was deliberate: annotation strategy shapes what the model can learn. Building the tool first forced clarity on what ground truth actually means for each object type in each sport.
Why this exists
  • Generic annotation tools don't support sports-specific event tagging (occlusion, contact, release, landing)
  • Predicted overlay in the same UI closes the retraining loop without exporting/importing between tools
  • Keyboard shortcut workflows make annotation fast enough to build datasets at scale
  • Deployed on Cloud Run — accessible from anywhere, no local setup for annotators

Four CV Systems · Built On Top
01
Cricket · Badminton
Ball & Shuttle Intelligence System
Continuous frame-wise trajectory tracking using TrackNet — fine-tuned on sport-specific annotated data from the ground truth engine above. Produces the coordinate stream that feeds every downstream speed, trajectory, and biomechanics system.
TrackNet · Fine-tuned
The Sports Problem
  • Manual ball tagging is too slow for large-scale analysis
  • Standard detectors fail on 3–5px fast-moving objects
  • Occlusion mid-delivery breaks frame-by-frame approaches
  • Speed estimation requires continuous trajectory, not sparse detections
Technical Approach
  • TrackNet takes 3-frame sequences — uses temporal context to infer position through blur/occlusion
  • Fine-tuned on annotated cricket & badminton footage with event labels
  • Trajectory smoothing removes false positives without losing real detections
  • Failure cases fed back into annotator for targeted dataset improvement
Value Delivered
  • Automated, scalable replacement for manual ball tagging
  • Speed estimation from trajectory delta across frames
  • Foundation coordinate stream for biomechanics & tactical systems
  • Works on broadcast footage — no custom camera required

02
Cricket · Badminton
Shot & Action Intelligence System
Temporal clip-based shot classification across cricket and badminton. 2–3 second clips capture the full motion arc of a shot — enough temporal context to distinguish shot types that look similar in a single frame. Replaces manual tagging entirely.
Temporal Modeling
The Sports Problem
  • Shot type labels are required for tactical analysis but tagging is slow and inconsistent at scale
  • Single-frame detection can't distinguish a drive from a cut — motion context is essential
  • Coaches need shot distribution data across entire training sessions, not just highlights
Technical Approach
  • Clip-level labeling — each clip is 2–3 seconds centered on the shot event
  • Temporal feature extraction captures motion patterns across frames, not just spatial shape
  • Confusion matrix analysis identified visually similar shot pairs — drove label refinement and data collection targeting those pairs specifically
Value Delivered
  • Automated shot tagging across full training sessions — zero manual effort post-setup
  • Shot distribution reports per player, per session, per phase
  • Player tendency profiling from shot selection patterns
  • Feeds directly into tactical modeling systems downstream

03
Badminton
Smash Technique & Biomechanics System
Video-only biomechanics pipeline that extracts smash speed and joint kinematics from raw training footage — no wearables, no special cameras. Uses shuttle trajectory from System 01 and player keypoints from pose estimation to derive objective technique metrics for coaching.
Video-Only · No Hardware
The Sports Problem
  • Smash quality is assessed subjectively — coaches use intuition, not data
  • Wearables are invasive, expensive, and don't work on archived footage
  • Players need objective consistency metrics, not just peak performance data
  • Academies need scalable technique analysis across many players simultaneously
Technical Approach
  • Shuttle velocity estimated from frame-delta of tracked trajectory coordinates
  • Mediapipe extracts 33 body keypoints per frame at 30fps on CPU
  • Joint angles computed from keypoint pairs across the smash motion arc
  • Attempt-wise comparison reveals consistency trends across multiple smashes
Value Delivered
  • Objective smash speed benchmarking from any training video
  • Technique consistency scores across sessions — not just peak metrics
  • Coaching reports generated automatically from raw footage
  • Works retrospectively on existing academy/match recordings
Stack MediapipeOpenCVPythonPose EstimationKinematics
04
Cricket
Audio–Visual Bat–Ball Contact Detection
Audio-first hit/miss detection system that identifies bat-ball contact events from short cricket clips. Works independently of clean visual frames — designed specifically for the conditions where visual-only detection fails: noisy nets sessions, occluded contact, fast pan cameras.
Audio-First · Multimodal
The Sports Problem
  • Shot segmentation requires knowing exactly when bat meets ball
  • Visual detection fails at the moment of contact — ball is occluded by bat
  • Training environments are noisy — multiple nets, background sounds
  • Frame rates often too low to capture sub-frame contact events visually
Technical Approach
  • Bat-ball contact produces a consistent acoustic signature regardless of visual occlusion
  • Audio features extracted and classified as hit/miss with threshold tuning for noise floor
  • Tested across indoor nets, outdoor grounds, and broadcast audio — different noise profiles
  • False positive analysis drove threshold calibration per environment type
Value Delivered
  • Reliable shot boundary detection in environments where visual detection fails
  • Automated shot segmentation from raw training footage
  • Reduces manual tagging effort for downstream classification systems
  • Can be deployed as the event anchor for any cricket CV pipeline
