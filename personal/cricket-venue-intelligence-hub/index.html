Cricket Venue Intelligence Hub

A Streamlit dashboard that profiles every IPL venue across pitch behaviour, phase-wise scoring, toss impact, and home-ground advantage. One intelligence view per ground — built on 2024 IPL ball-by-ball data, curated stadium reports, and KMeans-based venue clustering.

Live Demo ↗ GitHub ↗
What

An interactive Streamlit dashboard that gives you one intelligence view per IPL venue. For any ground, the app surfaces phase-wise scoring patterns, 1st-vs-2nd-innings averages, toss-decision impact, pace-vs-spin economy splits, boundary geometry, and dew effects.

Aggregates four data layers in one place — ball-by-ball deliveries, match metadata, hand-curated venue_profiles, and qualitative Stadium_Reports covering pitch type, outfield, bounce, weather, and dew impact.

Why

Generic "average score at venue X" stats hide what coaches and analysts actually need: which phase scores fastest here, whether toss really matters, how the boundary geometry favours one type of batter, and how dew swings the chasing-vs-batting-first calculus.

The Hub centralises those answers in one place, per ground, for every IPL venue — so a team's pre-match prep doesn't depend on flipping between five different spreadsheets and a memory of "Chinnaswamy always chases."

How
  • Data pipeline — merges deliveries_2024, matches_2024, venue_profiles, and Stadium_Reports on venue and match_id; normalises 6+ name variants per ground (e.g. "Ekana Cricket Stadium, Lucknow" → "BRSABV Ekana Cricket Stadium") so the same physical venue isn't double-counted.
  • Feature engineering — every ball tagged by phase: Powerplay (1–6), Middle Overs (7–15), Death Overs (16–20); per-venue aggregates compute run rate, strike rate, and balls-per-wicket by phase.
  • Venue clustering — KMeans + StandardScaler over engineered features groups grounds into behavioural archetypes (batting-friendly, spin-friendly, balanced, two-paced) rather than relying on subjective labels.
  • Analysis modules — 1st-vs-2nd-innings score deltas, toss-decision impact (bat-first win % vs chasing win %), pace-vs-spin economy split, boundary-dimension effects, dew impact scoring.
  • Stack — Python · Pandas · Scikit-learn (KMeans / StandardScaler) · Plotly / Matplotlib / Seaborn for charts · Streamlit for the front-end · deployed free on Streamlit Cloud.
Difficulties
  • Venue name disambiguation — the same ground was logged under 6+ different name spellings across seasons. Miss even one variant and a venue's numbers split into two ghost entries. Built a manual mapping table and kept growing it as new variants surfaced.
  • Joining qualitative + quantitative — Stadium_Reports contained hand-curated text fields like "Dry, Dusty" outfield or "Dew Impact: High"; had to model these consistently alongside numeric features without losing their nuance.
  • Cross-phase comparisons — raw run rates make the powerplay look slower than it really is (field restrictions vs early-overs caution). Reporting had to contextualise visually so users didn't draw the wrong conclusion.
  • Rebranded / shifted franchises — team–home-venue mappings drifted between seasons. Mapped franchises to their canonical home venue rather than redoing the join match-by-match.
