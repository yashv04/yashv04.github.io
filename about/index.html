02 / How I Think About The Work

Four principles I'll defend.

— 01

Pipeline beats model.

80% of every project I've shipped was clean data, careful joins, version control, and parsing edge cases. The model is the last 20% — and the model gets all the credit while the pipeline does all the work. I'd rather have a clean dataset and a logistic regression than a dirty one and a transformer.

— 02

Match the model to the data.

Reaching for XGBoost on 2,000 rows is a tell. On the ODI predictor I compared Logistic Regression, Random Forest, and XGBoost on a temporal validation set — LR won at 68.8% accuracy because 13 features on 2,005 rows is too small for tree boosting. Choose models for their inductive bias, not their reputation.

— 03

Honest metrics or none.

A 1.0 accuracy is a signal to investigate, not celebrate. Calibration matters more than peak accuracy — a well-calibrated 60% beats a miscalibrated 90% for any downstream decision. If I can write the label as a function of the features in five lines of pseudocode, I don't have a prediction problem.

— 04

Document obsessively.

This portfolio exists because I write about every project I ship — including what's broken. Each project page has a Limitations section that lists real bugs by line number. The writing isn't decoration; it's the work that turns a notebook into something defensible.

05 / Selectivity

What I won't do.

The work I'll defend has the work I won't do as its foundation. These aren't preferences — they're the lines that make the rest of what I ship credible.

  • → 01 Ship a model whose metrics I can't explain in plain English. If I can't tell you why a number is what it is, I haven't earned the right to claim it.
  • → 02 Hide failed experiments. Every project page on this site has a Limitations section that lists real bugs. Two projects have target leakage I left in and documented honestly. The failures teach more than the successes.
  • → 03 Claim expertise I don't have. I'm early-career, working at KhiladiPro, building toward elite sport. That's the truth. Saying I'm already at the highest level would close doors faster than admitting I'm not.
  • → 04 Use ML where a rule-based system is more honest. The Venue Intelligence Hub uses if/then rules and K-Means because they're the right tools — not because I couldn't reach for a neural net.
  • → 05 Use a random train/test split when temporal is honest. The ODI predictor's test set is 2024+ matches that the model never saw — even though it makes the headline number lower than a random split would. The lower honest number is the useful one.
